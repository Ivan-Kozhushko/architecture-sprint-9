| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1    | У клиента должна быть возможность подачи заявки на депозит через интернет-банк.| Клиенты должны видеть персонализированные ставки и подтверждать их СМС-кодом. |
| F2    | У клиента должна быть возможность подачи заявки на депозит через сайт. | Новые клиенты оставляют ФИО и телефон, после чего с ними связывается менеджер. |
| F3    | Отправка СМС-уведомлений клиентам. |Уведомление о подтверждении ставки и открытии депозита. |
| F4    | У клиента должна быть возможность просмотра ставок. | Клиенты должны иметь возможность видеть актуальные ставки. |
| F5    | Сотрудник отделения должен иметь возможность подать заявку напрямую в АБС, если клиент сразу придет в отделение, чтобы открыть депозит. | |
| F6    | Заявка на депозит, оформленная в интернет-банке, должна автоматически попасть в АБС. | |
| F7    | Заявка, размещенная пользователем на сайте должна автоматически попасть в ПО call-центра. | |
| F8    | Должен вестить централизованный расчет и ведение списка депозитов. | Все сотрудники, имеющие доступ в АБС, могут видеть актуальные данные по ставкам. Данные на сайте обновляются оттуда же. |
| F9    | Интернет-банк должен предоставлять список персонализированных предложений по депозитам. | В интернет-банке клиент должен видеть как общие, так и персонализированные ставки. |
| U   | Удобство использования (Usability) |              |
| U1    | Придерживаться системы дизайна принятой в компании. |              |
| U2    | Интерфейс открытия депозита должен быть максимально удобным для клиента. | Допущение: минимум шагов, необходимые подсказки, форма обратной связи по процессу открытия. |
| U3    | Функционал ведения ставок по депозитам и их согласование перенести из XLS-файлов в АБС. |              |
| R   | Надёжность (Reliability)           |              |
| R1    | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев. | Поэтому лучше избежать прямой работы интернет-банка с API АБС в новом процессе. |
| R2    | Должны быть реализованы требования к безопасности данных. | Полное шифрование трафика. |
| R3    | Предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД. | Учесть, что АБС может масштабироваться только вертикально из-за своей базы данных. |
| P   | Производительность (Performance)   |              |
| P1    | Время отклика по операциям должно составлять не более 200 миллисекунд при 95-м процентиле. | Допущение: на странице проведения платежей не ждать загрузки всех данных а сразу отобразить результат (скелетон-экран + ленивая загрузка). |
| S   | Поддерживаемость (Supportability)  |              |
| S1    | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке. | Например, базы данных MS SQL и Oracle. |
| S2    | Нужно разработать документацию для дальнейшего расширения системы. |              |
| +R  | + Ограничения (Restricitions)      |              |
| +1    | Функционал работы с СМС реализован в ядре системы и требует доработки со стороны подрядчика. | Этого лучше избежать. Реализовать такой бизнес-функционал можно силами команды разработки банка. |
| +2    | Новые технологии должны быть совместимы с существующими платформами разработки, а сотрудники понимали их на уровне ЯП. |              |
| +3    | Для очередей сообщений использовать Kafka. | Учесть, что ИБ необходимо доработать для работы с ней. |
| +4    | Выделить часть ИБ отвечающую за работы с депозитами в микросервис для будущего перевода на микросервисную архитектуру всего ИБ. |              |
| +5    | Нужно учитывать, что АБС может масштабироваться только вертикально из-за своей базы данных. |              |
| +6    | Данные клиентов полученные на сайте и в интернет банке необходимо шифровать при передаче. |              |
